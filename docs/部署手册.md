## 一、这是什么

Docker Butler 是一个 Docker 容器管理面板，专门解决 NAS 上容器的**日常维护痛点**：

- 🔁 每天定时启动/停止/重启/更新容器，不用手动点
- 📈 容器 CPU、内存、网络、磁盘实时监控
- 🚀 检测到新镜像一键更新，实时进度条
- 📦 Compose 项目可视化管理，网页直接新建项目
- 🧹 镜像清理、端口占用扫描
- 🔄 **面板自己能更新自己**，不用 SSH

## 二、部署原理

```
Docker 网络（bridge + pid:host）
└── docker-butler 容器 (privileged)
    ├── FastAPI (容器内 8383，映射宿主机 54321)
    ├── SQLite (./docker-butler-data/docker-butler.db)
    └── Docker SDK → /var/run/docker.sock → 管理本机其他容器
```

- **端口映射**：宿主机 54321 → 容器内 8383，端口可自定义
- **pid: host**：让"端口占用扫描"能读到宿主真实监听端口
- **数据目录**：`./docker-butler-data`（项目目录下，方便备份）

## 三、准备工作

1. ✅ 本机已安装 Docker 与 Docker Compose v2
2. ✅ 本机能正常访问 GitHub / Docker Hub（国内可配置镜像加速器）
3. ✅ 知道你的 NAS 存储路径（见下表）

| NAS 品牌 | 存储根 | Docker 项目目录 |
| --- | --- | --- |
| 飞牛 fnOS | `/vol1` | `/vol1/1000/Docker` |
| 群晖 Synology | `/volume1` | `/volume1/docker` |
| 绿联 UGREEN | `/volume1` | `/volume1/docker` |
| 威联通 QNAP | `/share` | `/share/Container` |
| 其它 Linux | `/` | `/opt/docker`（自定） |

## 四、部署启动

### 方式 A：git clone + Docker Compose（推荐）

```bash
# 1. 进入你的 Docker 项目目录（以飞牛为例）
cd /vol1/1000/Docker

# 2. 克隆仓库
git clone https://github.com/vindy-lu/docker-butler.git
cd docker-butler

sudo systemctl restart docker

# 4. 启动
docker compose up -d

# 5. 查看状态
docker ps | grep docker-butler
```

### 方式 B：Docker Compose 直接部署（不 clone 仓库）

新建 `docker-compose.yml`：

```yaml
services:
  docker-butler:
    image: ghcr.io/vindy-lu/docker-butler:latest
    container_name: docker-butler
    privileged: true          # 管理 Docker 需要特权模式，不能去掉
    pid: host                 # 让"端口占用扫描"能读取宿主监听端口
    ports:
      - "54321:8383"          # 宿主机端口:容器内端口 —— 想换端口改左边数字
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - ./docker-butler-data:/data    # 数据目录
      # 可选：Compose 项目浏览功能（不同 NAS 改默认值）
      - ${COMPOSE_ROOT:-/vol1/1000/Docker}:/host/compose
      - ${COMPOSE_VOLUME_ROOT:-/vol1}:/host-vol1
    environment:
      - TZ=Asia/Shanghai
      - DB_PATH=/data/docker-butler.db
      - APP_PORT=8383
      - COMPOSE_ROOT_HOST=${COMPOSE_ROOT:-/vol1/1000/Docker}
      - COMPOSE_VOLUME_ROOT_HOST=${COMPOSE_VOLUME_ROOT:-/vol1}
    restart: unless-stopped
```

然后 `docker compose up -d`。

### 方式 C：docker run 一条命令

```bash
docker run -d \
  --name docker-butler \
  --restart unless-stopped \
  --privileged \
  --pid host \
  -p 54321:8383 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v $(pwd)/docker-butler-data:/data \
  -e TZ=Asia/Shanghai \
  -e APP_PORT=8383 \
  ghcr.io/vindy-lu/docker-butler:latest
```

> 💡 可选：需要 Compose 目录浏览功能就追加 `-v /vol1/1000/Docker:/host/compose -v /vol1:/host-vol1`

## 六、核心功能一览

### 6.1 定时调度（最核心的功能 ⭐）

给容器设置定时任务：定时启动/停止/重启/更新。

**两种表达方式**：
- 📝 自然语言：直接输入「每天早上8点启动 nginx」「每5分钟检查更新」
- 🔢 Cron 表达式：`0 8 * * *`

操作路径：容器列表 → 点容器行「定时」按钮 → 新建任务。

### 6.2 一键更新

- 容器列表 → 点「更新」→ 实时进度条显示拉取/重建过程
- 支持「自动检查」：容器行开关打开后，面板自动检测新版本
- **面板自更新**：Compose 列表里本服务行 → 「检查更新」→ 有新版 → 「更新自己」，30 秒自动完成升级

### 6.3 Compose 项目管理

- 自动识别宿主机所有 Compose 项目（项目名/状态/更新时间一目了然）
- 项目级 启动/停止/重启/更新
- 点「详情」查看服务列表、YAML 配置、宿主机路径、资源占用
- 新建项目：网页粘贴 compose 内容即可，支持📂浏览目录选择位置、📁上传文件、🔌端口占用扫描
- 浏览目录时可 ⬆ 返回上级、＋ 新建子目录

### 6.4 镜像管理

- 镜像列表 + 使用状态标记 + 大小统计
- 一键清理未使用/悬空镜像

### 6.5 端口占用扫描 🔌

新建 Compose 项目时点「端口占用」，列出宿主机全部占用端口（系统监听 + 容器映射），选端口不踩雷。

## 七、常用命令速查

| 场景 | 命令 |
| --- | --- |
| 启动 | `docker compose up -d` |
| 停止 | `docker compose stop` |
| 重启 | `docker compose restart` |
| 看日志 | `docker compose logs -f` |
| 删除（保留数据） | `docker compose down` |
| 彻底删除（含数据） | `docker compose down -v` |
| 手动拉新镜像 | `docker compose pull` |

## 八、更新版本

### 面板自更新（推荐 ⭐）

```
1. Compose 列表 → 本服务行 → 点「检查更新」
2. 显示"有更新" → 点「更新自己」
3. 确认 → 面板离线约 30 秒 → 自动恢复
4. 重新登录 → Ctrl+F5 强刷
```

> 💡 面板会拉取新镜像、自动重建、清理旧镜像和临时容器，全程不用 SSH。

### 手动更新

```bash
cd /vol1/1000/Docker/docker-butler
docker compose pull
docker compose up -d
```

## 九、常见问题 FAQ

| 现象 | 解决办法 |
| --- | --- |
| 拉镜像失败 | 国内网络可在「镜像管理 → 加速器」配置国内加速器，保存后重启 Docker |
| 面板打不开 | `docker ps` 看状态，`docker compose logs -f` 看日志；端口 54321 是否被占用 |
| 提示 privileged 警告 | 管理其他容器需要特权模式，不能去掉 |
| 忘记 admin 密码 | `docker compose down && rm -rf ./docker-butler-data && docker compose up -d`(清空配置，慎用) |
| 端口占用扫描没有"系统监听" | 检查 compose 里 `pid: host` 是否还在（删了就读不到宿主监听） |
| 浏览器打开是旧页面 | Ctrl+F5 强刷（面板升级后前端有缓存） |
| Snap 版 Docker（Ubuntu 预装）部署失败 | Snap Docker 跑在沙箱里，**只能读写 `$HOME` 目录**（`/opt`、`/var/lib` 只读）。compose 里的数据目录/项目目录必须放 home 下（如 `/home/用户名/docker-butler/`），且「更新自己」要求 compose 文件本身也在 home 下（不能放 `/opt/1panel/...` 之类），否则自更新报 `read-only file system` |

## 附录：compose 配置说明

| 配置项 | 说明 |
| --- | --- |
| `ports: "54321:8383"` | 宿主机端口:容器内端口，左边可随意改 |
| `APP_PORT=8383` | 容器内监听端口，与 ports 右边保持一致 |
| `privileged: true` | 管理 Docker 必需，不能去掉 |
| `pid: host` | 端口占用扫描读宿主监听必需 |
| `./docker-butler-data:/data` | 数据目录（定时任务、设置、日志） |
| `COMPOSE_ROOT` | 宿主机 Docker 项目目录（目录浏览功能起点） |
| `COMPOSE_VOLUME_ROOT` | 宿主机存储根（允许上跳的浏览范围） |
